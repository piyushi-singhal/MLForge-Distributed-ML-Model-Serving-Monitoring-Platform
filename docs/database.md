# Database Schemas

MLForge uses PostgreSQL as its durable source of truth. To ensure strong microservice isolation, each service is allocated its own logically separated database schema (or distinct physical database/roles depending on the environment).

## 1. Authentication Database (`auth_db`)

### Table: `users`
| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | Integer | Primary Key, Auto-increment | Internal reference |
| `email` | String | Unique, Not Null, Indexed | User login email |
| `hashed_password` | String | Not Null | Bcrypt hashed password |
| `created_at` | DateTime | Default UTC Now | Registration timestamp |

## 2. Model Database (`model_db`)

### Table: `models`
| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | String | Primary Key | e.g. "churn-predictor" |
| `description` | String | Nullable | Human-readable context |
| `active_version` | String | Nullable | Pointer to the live `model_versions.id` |
| `created_at` | DateTime | Default UTC Now | Timestamp |

### Table: `model_versions`
| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | String | Primary Key | e.g. "v1" |
| `model_id` | String | Foreign Key (`models.id`) | Links to parent model |
| `artifact_path`| String | Not Null | OS Path to `.joblib` binary file |
| `metrics` | JSON | Nullable | Accuracy, F1-Score, etc. |
| `created_at` | DateTime | Default UTC Now | Timestamp |

## 3. Training Database (`training_db`)

### Table: `training_jobs`
| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | String | Primary Key | UUID generated by HTTP API |
| `model_id` | String | Not Null | Target model identifier |
| `algorithm` | String | Not Null | e.g., "random_forest" |
| `dataset_path` | String | Not Null | Data ingress location |
| `status` | String | Default "QUEUED" | QUEUED, RUNNING, COMPLETED, FAILED |
| `error_message`| String | Nullable | Stack trace on failure |
| `created_at` | DateTime | Default UTC Now | Timestamp |

### Table: `processed_events` (Idempotency Key Store)
| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `event_id` | String | Primary Key | RabbitMQ Message UUID |
| `status` | String | Default "RUNNING" | Tracks current state to detect crashed workers |
| `created_at` | DateTime | Default UTC Now | Timestamp |

## 4. Prediction Database (`prediction_db`)

### Table: `prediction_requests` (Audit Log)
| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | Integer | Primary Key, Auto-increment | Internal reference |
| `model_id` | String | Not Null | Model queried |
| `version_used` | String | Nullable | Exact binary version executed |
| `features_hash`| String | Not Null | SHA256 of input vector |
| `prediction` | String | Not Null | Result array/value |
| `latency_ms` | Float | Not Null | Time taken to compute |
| `cache_hit` | Boolean| Default False | Did Redis intercept this? |
| `created_at` | DateTime | Default UTC Now | Timestamp |
